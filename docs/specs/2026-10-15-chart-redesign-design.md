# Chart and presentation redesign: design

Date: 2026-10-15. Status: implemented (merged 2026-10-15). Updated 2026-10-21 to match what shipped:
light theme only (the dark versions were dropped in PR #1), an 11.5 × 7.2 in canvas, and numbered
panel headers (`style.panel_header`) instead of panel titles.
Comes before sub-project 4 (reference robustness), so that sub-project's new numbers flow into the
new figures by re-rendering.

## 1. Goal

The README's 12 charts are default matplotlib: inconsistent colours, raw column names as labels,
titles that ask a question instead of stating the answer, and charts of outputs (daily wiggles,
bars of means) rather than of mechanisms. They do not show that we understand why LPs lose to
arbitrage.

The audience is people hiring for DeFi trading and quant roles. **Success:** a reader who has never
heard of LVR understands the main finding from the README's first screen, and every figure:

- states its finding in the title, gives the key numbers in a subtitle and its source and main
  caveat in a footnote;
- uses one house style (palette, font, layout) (light theme only);
- is generated by `ulpe` from committed files in `results/` (no hand-drawn numbers);
- is rendered by tests from fixture data, byte-for-byte reproducibly.

Out of scope: an interactive dashboard, GitHub Pages, LinkedIn post text, new analysis. The
figures show existing results; where a figure needs a table the analysis does not yet write
(section 4), the analysis writes it, but computes nothing new beyond selecting and reshaping.

## 2. Approach

A separate figure layer:

- The analysis commands (`ulpe analyze`, `ulpe lp`) stop drawing. They write any extra tables the
  figures need to `results/figure_data/`.
- A new command, `ulpe figures`, reads only `results/` (including `results/figure_data/` and
  `summary.json`) and renders every figure in seconds. `ulpe all` runs it as its last step.
- A new package `src/uniswap_lp_economics/viz/` holds the style and one module per story chapter.
  It replaces `figures.py` and `lp/figures.py`, which are deleted.

Re-rendering never re-runs the replay, so iterating on the look is cheap; every number still
traces to a committed results file.

## 4. Figure data

Small committed CSVs in `results/figure_data/`, written by the step that owns the data, through the
existing atomic writers:

- **By `ulpe analyze`** (sub-project 2), for figure 3: `basis_hist.csv` (bin edges in bp and counts
  of block-start basis). Figure 3's gap survival is computed from `episodes.csv`, its lead–lag from
  `summary.json` `lead_lag`, and figure 8's waterfall from `summary.json` `arbitrage`, which the
  results already hold (as built).
- **By `ulpe lp`**, for figures 2 and 11:
  - **Episode selection:** the day with the largest measured LVR (0 s); within it, the 20-block
    window with the largest absolute Binance log move between its first and last block; the figure
    shows 32 blocks starting 4 blocks before that stretch (as built).
    `episode_blocks.csv`: per block, number, timestamp, pool price after the block, Binance price at
    block time, LVR (0 s) over the block's steps, and whether a searcher swap is in it.
    `episode_cex.csv`: Binance ETHUSDC, last trade price per second over the window.
  - **JIT block selection:** among JIT positions whose own transactions (the mint and burn
    transactions, as in `jit_own_swaps`) also hold a pool swap before the first add and one after
    the last removal, the one with the largest P&L vs rebalancing; ties broken by block number. `jit_block.csv`: the block's pool events in log
    order with kind, sender role (operator / other), amounts, pool price after the event, and the
    USD flows of section 3. If no JIT position meets the rule, the file holds the most profitable
    JIT position's block and a flag column saying the before/after swaps are absent; the figure
    states that in its subtitle.

The concept diagram needs no data. `ulpe figures` stops with a message naming the missing file
and the command that writes it when any input is absent.

## 5. Style system (`viz/style.py`)

- **Colour tokens** defined once: text, muted text, faint
  text, grid, background; and one meaning per colour in every figure: LVR red-brown, fees teal,
  JIT amber, other groups grey, plus fixed colours for protocol, builders, proposers and searchers.
- **`theme(mode)`**, a context manager that sets matplotlib's rcParams for the `"light"` theme.
- **`frame(fig, title, subtitle, source)`**: the title block (bold headline stating the finding,
  grey subtitle, footnote with source and caveat) on a fixed canvas (11.5 × 7.2 in) with fixed
  margins, so figures line up. Multi-panel figures use the same width.
- **Helpers:** USD / percent / bp formatters; direct labels at line ends (no legends where a label
  fits); fading interval bands; a "spans zero" marker.
- **Font:** Inter (SIL Open Font License), regular, semibold and bold TTFs in `assets/fonts/` with
  the licence file, registered with matplotlib at import. If a font file is missing, rendering
  raises instead of falling back.

## 6. The "$10k" framing

Figure 10 and the README state P&L as USD per $10,000 of time-weighted position value per 30 days:
`bp_per_day × 30` (because `bp_per_day` is P&L per 10⁴ of value per day). For example −1.35 bp/day
is about −$40 per $10,000 per month. Intervals scale the same way. Tables keep bp/day.

## 7. Outputs

- Each figure (except the GIF) as `results/figures/<stem>.svg`.
  - Text is converted to outlines (`svg.fonttype = "path"`), so GitHub shows Inter without having
    it.
  - SVG metadata has no date, and `svg.hashsalt` is fixed, so a re-render with unchanged inputs
    leaves the files byte-identical.
- `results/figures/00_hero.png`: 1280×640 social card (light).
- `results/figures/02_stale_pool_episode.gif`: on a white card, written with matplotlib's Pillow writer (Pillow is already a matplotlib dependency).
- The README embeds each figure as a plain `<img src="….svg" alt="…">`.

## 8. Testing

- **Style:** formatters; the palette defines every token; the font is registered, and a missing
  font file raises.
- **Every figure function:** renders from small fixture tables; writes valid SVGs
  with no date metadata; rendering twice gives identical bytes. The GIF test renders a short
  fixture window and checks the frame count.
- **Figure-data writers:** the synthetic end-to-end worlds of sub-projects 2 and 3 produce every
  `figure_data` file with the expected columns. The two selection rules are tested on small
  synthetic cases (including the JIT fallback).
- **`ulpe figures`:** runs from a fixture `results/` directory and writes every expected file;
  a missing input exits with the file and command named.
- No pixel-diff tests: every real render is checked by eye and shown before it is committed.

## 9. README and docs

- README reordered into the chapters of section 3: hero at the top, then the TL;DR findings, each
  chapter with its figure(s) and the existing tables and caveats. The findings' text and numbers
  do not change, except where a figure's subtitle needs a number from `summary.json` that the text
  then quotes the same way.
- `docs/methodology.md`: a figures section listing each figure and its inputs, the two selection
  rules of section 4, and the "$10k" definition.
- Repo map: `viz/`, `assets/fonts/`, `results/figure_data/`; `ulpe figures` in the reproduce
  steps.
- The GitHub social preview image (`00_hero.png`) is set by hand in the repository settings; the
  README says which file it is.

## 10. Risks

- **Clutter:** 13 figures plus a GIF is more than now. Each chapter has one main figure; figure 7
  and figure 12 can move below the fold of their chapter.
- **SVG size:** outlined text makes SVGs larger (tens of KB each); acceptable on GitHub.
- **Sankey layout** in matplotlib has no built-in suitable for this; it is drawn with patches
  (rectangles and Bézier bands). If it cannot be made legible, fall back to a horizontal stacked
  bar with the same colours and labels, and say so in the review.
